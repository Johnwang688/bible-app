# Open Bible

A Bible study app for teenagers and young adults — Scripture reading, AI-assisted study, chapter summaries, quizzes, and people/places/themes exploration.

The backend and internal docs use the name **Logos Light**.

## Features

- **Reader** — Multiple translations, typography controls, page-flip navigation, highlights, and reading progress
- **AI assistant** — Chat grounded in Scripture and commentary; guided chapter study; entity overviews for themes, people, and places
- **Commentary** — Matthew Henry and authored chapter summaries (Treasury of Scripture Knowledge cross-references are planned; the data is not loaded yet)
- **Quizzes & mastery** — Chapter quizzes with hints, rewards, and progress tracking
- **Entity pages** — Browse themes, people, and places linked from chapter summaries

## Tech stack

| Layer      | Technology                                      |
| ---------- | ----------------------------------------------- |
| Backend    | Python 3.12+ + FastAPI (the Docker image uses 3.12) |
| Frontend   | Next.js 15 (React 19, TypeScript, Turbopack)    |
| Content    | SQLite file built from `content/source/` (FTS5 search) |
| User data  | Supabase (PostgreSQL + Row Level Security), moving to Firestore |
| Auth       | Supabase Auth (email and password; Google sign-in is not implemented yet), moving to Firebase Auth |
| AI         | OpenAI (default) or Claude Haiku 5.5 via `AI_PROVIDER` |
| Deployment | Google Cloud Run (`deploy.py`)                  |

## Getting started

### Prerequisites

- Python 3.12+
- Node.js 20+
- A [Supabase](https://supabase.com) project
- For AI features, depending on `AI_PROVIDER`: an [OpenAI API key](https://platform.openai.com) (`openai`, the default), an Anthropic API key (`anthropic`), or Google Cloud Application Default Credentials (`vertex`: `gcloud auth application-default login`)

### 1. Backend

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate

# macOS / Linux
source .venv/bin/activate

pip install -r requirements.txt
cp .env.example .env   # fill in keys (see below)
```

Build the content database (Bible text, commentary, summaries, entities, quiz questions). It takes a few seconds and is verified against `content/source/MANIFEST.json`:

```bash
python scripts/build_content.py
```

User data, auth and quiz progress still use Supabase for now: apply `supabase/migrations/` to your project.

**Changing content** (summaries, quiz questions, translations): the app serves what is in `content/source/`, not what is in Supabase. The old loaders (`scripts/load_summary.py`, `scripts/load_usfx_translation.py`) still write to Supabase, so after loading, re-export with `python scripts/export_supabase.py --content-only` (updates `content/source/` and its manifest) and rebuild with `python scripts/build_content.py`. A direct authoring path into `content/source/` is planned.

Start the API:

```bash
uvicorn app.main:app --reload --port 8000
```

API docs: [http://localhost:8000/docs](http://localhost:8000/docs)

### 2. Frontend

```bash
cd frontend-next
npm install
npm run dev
```

App: [http://localhost:3000](http://localhost:3000)

The frontend rewrites `/api/*` to the backend. Override with `BACKEND_URL` if needed.

### 3. Run both (Unix)

```bash
bash start.sh
```

## Environment variables

Copy `.env.example` to `.env` at the repo root.

| Variable | Required | Purpose |
| -------- | -------- | ------- |
| `SUPABASE_URL` | Yes | Supabase project URL |
| `SUPABASE_ANON_KEY` | Yes | Public anon key |
| `SUPABASE_SERVICE_ROLE_KEY` | Yes | Server-side DB access |
| `AI_PROVIDER` | No | `openai` (default), `anthropic` or `vertex` |
| `OPENAI_API_KEY` | For OpenAI | Chat and entity content |
| `OPENAI_MODEL` | No | Defaults to `gpt-5.4-nano` |
| `ANTHROPIC_API_KEY` | For `anthropic` | Claude API key |
| `CLAUDE_MODEL` | No | Defaults to `claude-haiku-5-5` |
| `VERTEX_PROJECT_ID`, `VERTEX_REGION` | For `vertex` | Claude on Google Cloud (region defaults to `global`); credentials come from Application Default Credentials |
| `AI_MAX_INPUT_TOKENS`, `AI_MAX_TOOL_ROUNDS` | No | Claude request budget (defaults 100000 and 6) |
| `CONTENT_DB_PATH` | No | Defaults to `build/content.sqlite` |
| `APP_ENV` | No | `development` or production |
| `CORS_ORIGINS` | No | Comma-separated allowed origins |
| `DEV_ACCOUNT_EMAIL` | No | Dev wallet floor for a test account |
| `GEMINI_API_KEY` | No | Quiz batch generation scripts only |

See `app/core/config.py` for the full settings list.

## Bible translations

With text: **WEB** (default), **ASV**, **CUV** (Traditional), **CUV-SIMP** (Simplified). KJV and BSB are listed but have no text yet, so the picker hides them.

Translations live in `content/source/verses/<ID>.jsonl` and are built into the content database.

## Commentary sources

MVP uses public-domain and openly licensed sources:

- **Matthew Henry's Concise Commentary**
- **Treasury of Scripture Knowledge** (cross-references): listed as a source, but the cross-reference data has not been loaded yet
- **Chapter summaries** — authored in `commentary/`; served from `content/source/commentaries.jsonl` (see "Changing content" above)

> Dr. Constable's Expository Notes are not redistributable without permission and are not included.

## AI assistant

The AI layer lives in `app/services/ai_service.py` (OpenAI path) and `app/services/claude_agent.py` (Claude path: tool use over the content database for passages, search, commentary and people/places), with composable prompts in `app/prompts/ai/`. `AI_PROVIDER` picks the backend. It handles:

- Sidebar chat with navigation actions (go to passage, highlight, search)
- Guided chapter study (section breakdowns and deep dives)
- On-demand entity content for theme/person/place pages

Rate limiting is applied per IP for unauthenticated requests.

Live eval for the Claude path (30 cases with a verse-fidelity check; needs a key and costs a few cents):

```bash
AI_PROVIDER=anthropic ANTHROPIC_API_KEY=... python scripts/run_ai_eval.py
python scripts/run_ai_eval.py --dry-run   # offline check of the harness
```

## Quizzes

Quiz questions are authored as JSON in `quiz-questions/`. The served copy is `content/source/quiz_question_bank.jsonl` (built into the content database); quiz progress and rewards are still stored in Supabase. See [`quiz-questions/README.md`](quiz-questions/README.md) for the Gemini batch generation workflow.

## Deployment

```bash
python deploy.py              # backend + frontend to Cloud Run
python deploy.py --dry-run    # print commands without running
python deploy.py --backend-only
python deploy.py --frontend-only
```

Requires an authenticated `gcloud` CLI. The backend image builds `content.sqlite` from `content/source/` during `docker build`. Override defaults with `DEPLOY_PROJECT`, `DEPLOY_REGION`, and `DEPLOY_BACKEND_URL`.
